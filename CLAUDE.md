# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Krupno is a Windows AI image upscaler: a WPF window (`Krupno.exe`) and a command-line tool (`krupno-cli.exe`) over one library, running ONNX models through Windows ML (ONNX Runtime with DirectML, plus the vendors' execution providers on Windows 11 24H2+). .NET 10, x64 only, `net10.0-windows10.0.19041.0`.

The docs are detailed and up to date; read the relevant one before changing behavior:
- `docs/how-it-works.md`: tiling, memory, accelerators, color, animations, and the finer points of the window and the CLI.
- `docs/development.md`: layout, tests, CI, translations.
- `docs/installer.md`: installer, portable ZIP, releases, package managers.
- `docs/models.md`: converting PyTorch weights to ONNX, model comparison, publishing a model release.

## Commands

```bash
dotnet build Krupno.slnx -c Release
dotnet test tests/Krupno.Core.Tests -c Release                                             # unit tests (xUnit v3), a few seconds
dotnet test tests/Krupno.Core.Tests -c Release --filter "FullyQualifiedName~TilePlannerTests"  # one class or test
```

Synthetic end-to-end tests run the Release `krupno-cli.exe` against the tiny models in `tests/fixtures/models`, whose output is known to the pixel (needs Python with numpy and Pillow, `pip install -r tests/requirements.txt`):

```bash
powershell -ExecutionPolicy Bypass -File tests\run_cli_tests.ps1
```

`-CheckFallback` is for a machine without a GPU (CI): it makes every GPU run fall back to the CPU and fails on a real GPU. Results and logs go to `tests/out/cli`. `python tests/make_fixtures.py --models` regenerates the fixture models (needs `onnx`).

UI scripts (`tests\gui_states.ps1`, `tests\gui_keys.ps1`, `tests\readme_screenshot.ps1`) drive the window through UI Automation, need real models in `models/` and a desktop, and are not run in CI. They temporarily replace `%LOCALAPPDATA%\Krupno\settings.json`.

Installer and portable ZIP (needs Inno Setup 6.5+): `powershell -ExecutionPolicy Bypass -File installer\build.ps1`, output in `artifacts/`.

Environment variables for testing: `KRUPNO_BASIC_RENDER_DRIVER=1` (treat the software adapter as a GPU), `KRUPNO_THEME=light|dark`, `KRUPNO_UPDATE_FROM=<version>` (pretend to be another version for the update check).

## Architecture

All processing lives in `src/Krupno.Core` (`Processing/Upscaler.cs` is the pipeline); the window (`src/Krupno.App`) and the CLI (`src/Krupno.Cli`) are thin front ends over it. What the code doesn't make obvious:

- `Krupno.Core` sets `UseWPF` only for the WIC codecs (`System.Windows.Media.Imaging`); it has no UI.
- Model metadata is read from `krupno.*` keys written by `tools/convert_to_onnx.py`; models converted before the rename carry `upscalr.*`, which must keep working. A model without metadata is probed.
- `UpscaleModel` keeps a few `InferenceSession`s keyed by input window size: DirectML and the accelerators compile the graph per shape, so all tiles of an image share one window size.
- The CLI forces the invariant culture, so its output stays English for scripts.
- `ViewModels/MainViewModel.cs` is one large view model that owns the run, the queue, settings, accelerators and updates.
- Known model file names get their titles in the window from `ViewModels/ModelItem.cs` and in the installer from `installer/messages.iss`.
- `tests/Krupno.Core.Tests` compiles several files from `src/Krupno.App/Infrastructure` directly (see its `.csproj`), so those files must stay free of WPF.

## Translations

User-facing text lives in `Properties/Strings.resx` (English) plus `Strings.<culture>.resx` for 15 languages, in both `Krupno.App` (the window) and `Krupno.Core` (progress and errors). A new key must go into every translation, and `Strings.Designer.cs` must be updated to match, since it is normally regenerated by Visual Studio or Rider. Plural texts hold one form per plural category separated by `|` (rules in `Krupno.Core/Localization/Plurals.cs`). `LocalizationTests` fails on missing keys, mismatched placeholders, wrong plural counts, a stale designer file, unused keys, and installer messages missing a language. The log, "Copy error details" and the CLI stay in English.

## Conventions

- Code, comments, docs, commit messages and PRs are in English; other languages appear only in the translation files.
- Behavior changes go together with their docs: the README for users, `docs/how-it-works.md` for details, and the CLI's `--help` text in `CliOptions`.
- Commit and PR titles are plain sentences describing the change ("Add ...", "Fix ...", "Version 0.2.6").
- CI (`.github/workflows/tests.yml`) squash-merges a pull request from this repository and deletes its branch as soon as the tests pass. Open a draft if the change should not be merged yet. Dependabot PRs are merged by hand, since the CI runner has no GPU.
- Releases of the app and of models: see `docs/installer.md`. Published model releases (`models-v1`…`models-v4`) are never overwritten, since built installers point to them; a new set of models goes into the next `models-vN`.
